# Cross-Page Consistency Audit — Re-check, September 2026

Scope: this is a re-run of audit #7 from the original menu (`docs/cross-page-consistency-audit-2026-09.md`, September 8), one of three "oldest, never redone" audits alongside interactive-correctness and content-flow (design was picked and redone on 2026-09-17). Same territory as the original — wayfinding elements that appear identically-styled on nearly every page: hero eyebrow badges, `BreadcrumbList` JSON-LD, home-page tool-card badges, and the `NAV`/`kind` taxonomy — re-checked for internal consistency and, this time, also cross-checked against each *other*, since the two real bugs found below are exactly that: two systems that each *looked* internally consistent on their own but disagreed with each other.

Method: re-extracted every page's hero-eyebrow text, `BreadcrumbList` JSON-LD, and home-page `tool-card-num` badge, and diffed all three against each other and against `NAV` order in `js/main.js`, since ten days of other audits' edits (design, link, technical, accessibility, navigation, performance) had already renumbered some of these once (the original report's laser-cooling/absorption-imaging and remote-entanglement fixes) — the question this pass asked was whether every place a category name or sequence number appears got updated in step with those earlier fixes, or whether any copy was left behind. Cross-checked every candidate against `docs/page-notes/*.md` and prior audit reports before touching anything.

## Fixed

- **`BreadcrumbList` JSON-LD on all 7 `Trap, Image & Cool` pages (`imaging-calculator`, `release-recapture`, `tof-calculator`, `lab-calculators`, `absorption-imaging`, `laser-cooling`, `cooling-simulator`) named the category "Measure & Cool"**, while the hero eyebrow badge, the `NAV` dropdown label, and the home page's own section intro all call it "Trap, Image & Cool." "Measure & Cool" was the category's name before an earlier rename (confirmed via git history — a `js/main.js` comment still references the old name too, see "Not covered" below); the breadcrumb copy on all 7 pages was never updated when the UI-facing name changed. All 7 breadcrumbs agreed *with each other*, which is why the original audit's "internal consistency within each category" check didn't catch it — this pass added a check across the different display systems (eyebrow vs. breadcrumb vs. home badge) for the same category, not just within one system. Renamed all 7 to "Trap, Image & Cool."
- **`index.html` (the GitHub Pages root redirect) was missing `og:image`/`og:image:width/height/alt` and all four `twitter:*` tags** that every other real page (including its own redirect target, `home.html`) carries — it does have its own `canonical`, `og:url`, `og:title`, `og:description`, so it's clearly meant to be indexable at the bare domain, unlike `404.html` (which correctly has none of this, since it isn't a real page). Added the same image and Twitter-card tags `home.html` uses.
- **Home page's tools-grid `tool-card-num` badges had drifted out of sync with 4 pages' own hero-eyebrow numbers**, left behind by the original audit's Sep-8 renumbering (which fixed the eyebrows and breadcrumbs but didn't touch this third place the same sequence number appears): `remote-entanglement.html`'s home card said "QC 04" while its own page says "Quantum 06"; `rb-explorer.html`'s home card said "QC 05" vs. its own "Quantum 04"; `dd-playground.html`'s said "QC 06" vs. its own "Quantum 05"; `cooling-simulator.html`'s said "TRAP 06" vs. its own "Trap, Image & Cool 07." A visitor scanning the grid would see one number, land on the page, and see a different one. Updated all 4 home-card badges to match each page's own eyebrow number. (Confirmed the DOM *order* of tools-grid cards is not itself in strict category order — cards for the same category are interleaved throughout the grid — but that appears to be a deliberate visual-layout choice independent of the badge numbers, not something this pass touched; only the badge *text* was wrong.)

Grepped the whole repo afterward for any other stale copy of the old numbers/name (`llms.txt`, `llms-full.txt`, `sitemap.xml`, `README`, `CLAUDE.md`) — none found; the drift was confined to the three spots fixed above. All fixes are text/value substitutions with no structural changes. Tag-balance (div/ul/li/tr/td/section/table/span/a) was checked on every file touched and came back balanced. `tests/formula_regression.py` was re-run after each batch and stayed 11/11 throughout. No shared CSS/JS files were touched, so no cache-bust bump was needed this round.
