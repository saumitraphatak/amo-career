Scope: how pages connect to each other and how a visitor finds their way around — the global nav dropdown and mobile overlay, the global search index, footer links, "See Also" cross-linking, in-page anchor integrity, click-depth/discoverability from `home.html`, the Guided Paths section, and visible vs. structured-data-only breadcrumbs. This is the last of the four audits originally deferred on 2026-09-08 (cross-page consistency and accessibility are now both done too — all 8 items from the original menu are complete as of this run). Deliberately did not re-check ground already covered: hero-eyebrow/breadcrumb-JSON-LD/kind-taxonomy consistency (cross-page-consistency audit), sitemap/meta-tag/page-count staleness (technical audit, though see the one small regression caught below), page-level link rot (link audit), or `<main>`/ARIA/keyboard mechanics (accessibility audit, just completed).

Method: delegated a research-only pass to a subagent (same pattern as prior audits) with an explicit list of what NOT to re-cover, since the risk on a 4th-in-a-row audit of the same site is re-litigating settled ground instead of finding new territory. Verified every finding against the actual files/code before changing anything — in particular, traced the exact DOM structure behind the most significant finding (a duplicate "related tools" panel bug) by hand before fixing it, since the research pass's description of *where* the two panels came from needed confirming against the real render order. Regression suite (11/11) kept green throughout; tag-balance checked on `home.html` (the only page HTML touched this round).

## Fixed

- **A real bug: every tool page except `decoherence-lab.html` was silently rendering two different, sometimes-contradictory "related tools" panels back to back.** A static, hand-curated `<section class="see-also">` exists on 27 of 28 pages. Separately, `initRelatedToolsPanel()` in `js/main.js` runs on every page load and auto-injects its *own* `<section class="see-also auto-related-tools">` from a `RELATED_TOOLS` map — but its "don't add a duplicate" guard checked `document.querySelector('.auto-related-tools')`, a class that can't exist until the function itself creates it, so the guard could never actually fire. Net effect on every one of those 27 pages: two "related tools" sections, and their suggested links frequently disagreed (e.g. `mot-designer.html`'s hand-written block suggests `laser-cooling`; its auto-generated one suggests `atom-library` instead). This is clearly not an intentional redundancy — the guard's own name and logic show the code was always meant to prevent exactly this. Fixed by broadening the guard to `document.querySelector('.see-also')` (matches either panel type), so the auto-panel now only fires on pages with no related-tools section at all — currently just `decoherence-lab.html`, where it was already working correctly and topically sound. No page HTML was touched; this is a one-line JS fix that changes rendered output on 27 pages.
- **Mobile nav links were missing the `kind` subtitle** ("Calculator" / "Guide" / "Simulator" / etc.) that desktop dropdown links already show via `itemHTML` in `js/main.js` — `mobileItemHTML` just rendered the bare label. Added the same conditional `<small>` block so mobile visitors get the same at-a-glance taxonomy signal desktop visitors do.
- **Global search index had zero keywords for 6 of 28 tool pages** (`cavity-qed`, `vacuum-systems`, `tweezer-designer`, `absorption-imaging`, `decoherence-lab`, `remote-entanglement`) and for all 14 `NAV.learn` sub-topic anchors on `learn-quantum.html` — these fell back to title-word-only matching, so a synonym search (e.g. "Purcell" for cavity-qed, "UHV" for vacuum-systems, "CNOT" for the Quantum Gates section) would find nothing. Added keyword strings in the same style as sibling entries for all 20 gaps. Also closed a smaller inconsistency: `atom-library.html` only listed the abbreviation "Rb" while its sibling comparison page `rb87-vs-yb171.html` also matches the full word "rubidium" — added the full element names to `atom-library`'s keywords so the two Rb-related pages behave consistently.
- **`zernike.html` and `cavity-qed.html` were both live in `NAV.build`, the nav dropdown, and the homepage tools-grid, but missing from `home.html`'s Build footer column** (8 of 10 build tools were listed, not 10). Added both `.footer-link` entries in their correct `NAV.build` position (between Polarimetry and Vacuum Systems).
- **Housekeeping regression from the technical audit**: `README.md` and `CLAUDE.md` both still said "27" in their file-structure comments (`# 27 tool and content pages`, `(27 files)`) despite `CLAUDE.md`'s own "Page count is 28" note elsewhere and `llms.txt` correctly saying 28 — a two-line staleness the technical audit's own fix apparently didn't reach. Corrected both to 28.
- **`CLAUDE.md` documented a footer structure that no longer matches the shipped site.** It claimed "one `.footer-links` column per category (Build / Measure & Cool / Quantum / Career)" — 4 columns 1:1 with `NAV` categories — but the real footer has 3 columns with a different, evidently intentional grouping (Build; Measure & QC, which absorbs most of `quantum` plus `absorption-imaging`; Learn & Career, which absorbs `cooling` and the rest of `quantum`/`career`). Rewrote the two relevant `CLAUDE.md` passages to describe the actual 3-column grouping so the "add a footer link" instructions don't send a future editor looking for a 4th column that doesn't exist. Not a site change — documentation only.
- Bumped `main.js?v=23→24` (styles.css unchanged this round) across every page, `home.html`, and `404.html`; grep-verified exactly one version string remains.

## Flagged, not changed — needs your call

- **3 of 28 tools have no dedicated card in `home.html`'s main tools-grid**: `laser-cooling`, `learn-quantum`, `rb87-vs-yb171`. All three are still reachable from `home.html` through other visible paths (guided-path steps, the footer, and — for `rb87-vs-yb171` — an intent card), so none are orphaned by the strict reachability bar, but they're the only 3 of 28 with no entry in the primary "browse by workflow" grid. This reads like it could be intentional — all three are comparison/overview/learning-path pages rather than single-purpose calculators, which might be exactly why they were left out of a grid of tool *cards* — but I didn't want to guess and add cards that might not belong there.
- **7 of 28 tools appear in none of the 6 "Guided Paths"** on `home.html` (`cavity-qed`, `vacuum-systems`, `tweezer-designer`, `absorption-imaging`, `decoherence-lab`, `dd-playground`, `remote-entanglement`) — a visitor following "Where should you start?" would never be routed to a quarter of the catalog. Fixing this means either adding a 7th path or working these into existing ones, which changes the actual editorial content of that section (what order/grouping best represents a learning journey) — a judgment call, not a mechanical fix. Verified while looking at this that the "concept-map graph" below the path cards genuinely reads the path-card DOM live with no separate duplicated dataset (confirming the existing page-note's claim still holds), so fixing the path cards is the only thing that would need to happen — no second copy of this data exists to keep in sync.
- **No visible breadcrumb trail exists anywhere on the site** — every tool page carries an invisible `BreadcrumbList` JSON-LD block (SEO/rich-snippet only, already checked for internal consistency by the cross-page-consistency audit), but there's no rendered "Home › Quantum › Rydberg Blockade Lab"-style UI element a human visitor would actually see. Orientation currently relies entirely on the nav dropdown's active-category highlighting. Adding a visible breadcrumb component would touch the shared page template and change every page's look — flagging as a possible future enhancement rather than doing it unasked.
