# Accessibility Audit — September 2026

Scope: a WCAG-style pass over all 28 tool pages plus `home.html` and `404.html`, covering keyboard operability, ARIA correctness on custom widgets (accordions, tabs, hand-rolled toggles), form-control labeling, landmark structure, focus visibility, decorative-icon signaling, motion sensitivity, and data-table markup. This is audit #8 of the original 8-item menu (the last of the four originally deferred — cross-page consistency was already completed on 2026-09-08; accessibility, navigation/IA, and performance were the three still outstanding, and this is accessibility). Color contrast and heading-hierarchy issues were also investigated as part of this pass since they're classic WCAG concerns, even though one of them (heading hierarchy) had already been flagged by the design audit as "belongs to a future accessibility audit."

Method: delegated a research-only pass to a subagent (same approach the interactive-correctness and design audits used) to grep/read across all 30 files and report concrete file:line findings without editing anything, since the surface area (28 pages × many repeated widget patterns) would have blown up a single context. Verified every finding against the actual files before touching anything — this caught two real mistakes in the raw research (see "Corrections during verification" below) that would have produced wrong fixes if applied blindly. All fixes were applied with small Python scripts operating on exact string/structural anchors (never blind line-number edits), with tag-balance checks (div/ul/li/tr/td/th/table/section/main/footer/span/button/svg) run after every batch and the regression suite kept green throughout (11/11 PASS, checked after each batch, final state confirmed green).

## Fixed

- **Scroll-reveal animations had no `prefers-reduced-motion` guard.** The `.anim-in`/`.anim-in.visible`/`.anim-in.delay-N` transition rules (`css/styles.css`) played a 20px slide + fade on every element site-wide with no way to opt out — a real vestibular-disorder concern (WCAG 2.3.3) that the design audit had already flagged as "belongs to a future accessibility audit." Added a `@media (prefers-reduced-motion: reduce)` block that collapses the transition to none and shows content at its resting state immediately.
- **All primary/ghost CTA buttons (`.btn`) had `outline: none` with no replacement focus style anywhere in the file** — a genuine WCAG 2.4.7 failure; every button-styled link/button on the site was keyboard-invisible when tabbed to. Added `.btn:focus-visible { outline: 2px solid …; outline-offset: 2px; }`.
- **19 of 28 tool pages (plus `home.html`) used a plain `<div id="main-content">` as the skip-link's target instead of a real `<main>` landmark**, so screen-reader users navigating by landmark got no "main content" region at all on most of the site. Retagged to `<main>` on: atom-library, cooling-simulator, fidelity-budget, imaging-calculator, lab-calculators, lab-techniques, laser-cooling, laser-locking, mot-designer, polarimetry, qc-landscape, rb-explorer, rb87-vs-yb171, release-recapture, rydberg-calculator, tof-calculator, vacuum-systems, zernike. Verified via depth-tracing (not just the nearest `</div>`) that each page's real content boundary was found correctly before retagging — see "Corrections during verification."
- **`dd-playground.html`'s skip-link target was a genuinely empty `<div id="main-content"></div>`** sitting one line above the real hero content, while the actual page wrapper had no id at all. Moved `id="main-content"` onto the real wrapping element (now `<main>`) and removed the now-redundant empty div.
- **`learn-quantum.html` already had a real `<main class="container">` landmark nested inside an outer `<div class="page-wrap" id="main-content">`** — a leftover from a past refactor that put the skip-link id on the *outer* wrapper (which includes the sticky topic-nav) instead of the actual `<main>`. Moved `id="main-content"` onto the existing `<main>` tag so "skip to content" actually skips past the topic-nav now, and left the outer div as a plain div (no duplicate `<main>` landmark).
- **`home.html`'s skip-link target (`id="main-content"`) was on the hero `<section>` only** — every other section (`#intent-paths`, `#tools`, `#qc-industry`, `#learn`, `#paths`, `#about`) was outside any main landmark. Wrapped all of them in a new `<main id="main-content">…</main>` between the nav and the footer, and removed the id from the hero section (kept its `aria-label="Hero"`).
- **Tab widgets (`.tab-bar`/`.tab-btn`/`.tab-panel`, used on 9 pages) had zero ARIA semantics** — `initTabs()` only toggled a CSS class, so a screen reader saw plain unlabeled buttons with no indication they formed a tab group. Updated `initTabs()` in `js/main.js` to set `role="tablist"` on the bar, `role="tab"` + `aria-selected` (kept in sync on click) on each button, and `role="tabpanel"` on the panels it controls. This is a JS-only fix, applied uniformly to every tab bar site-wide without touching page HTML.
- **29 accordion headers across 4 pages were `<div>` instead of `<button>`** (atom-library.html ×16, cavity-qed.html ×3, lab-calculators.html ×1, lab-techniques.html ×9) — keyboard-unreachable, since `initAccordions()` only binds a `click` listener with no keyboard fallback, unlike the majority-pattern `<button class="accordion-header">` used correctly elsewhere on the same site. Converted all 29 to real `<button type="button">` (adding `aria-expanded="false"` where it was missing entirely), matching the site's own established correct pattern. Confirmed `.accordion-header`'s CSS (`display:flex; width:100%; border:none; background:…; text-align:left`) already fully overrides button user-agent styling — visually identical, and no nested interactive elements were found inside any converted header (would have made the button invalid).
- **~26 hand-rolled clickable `<div>`s were mouse-only**, with `onclick` but no `tabindex`/`role`/keyboard handler: atom-library.html's 15 `.atom-tile` species-picker tiles, learn-quantum.html's 6 `.bell-card` state-selector tiles, remote-entanglement.html's 5 `.approach-head` and vacuum-systems.html's 4 `.pump-card-head` hand-rolled accordion toggles. Added `tabindex="0" role="button"` plus an `onkeydown` handler mirroring the existing `onclick` (Enter/Space), following the exact pattern the site already uses correctly on `amo-groups.html:1155`. For the two hand-rolled-accordion cases, the toggle now also syncs `aria-expanded` on click and keydown (there was no ARIA state at all before).
- **196 `<th>` elements across 25 pages (plus 12 more using bare `<tr><th>` with no `<thead>` wrapper at all, on `decoherence-lab.html` and `lab-calculators.html`) had zero `scope` attributes** — every data table's headers were visually-only, unconnected to their cells for screen-reader users navigating cell-by-cell. Added `scope="col"` to every column-header `<th>` site-wide (232 total, purely additive, no visual change). Also fixed the JS-generated Clebsch–Gordan table (`lab-calculators.html`'s `buildTable()`): its row headers were `<td class="row-label">` (styled to look like headers but not marked as headers at all) — converted to `<th scope="row" class="row-label">` and added a matching `table.cgt th.row-label` CSS rule so the visual style (which was written for a `td` selector) still applies now that the tag changed.
- **75 decorative chevron `<svg>` icons (accordion-chevron ×61, topic-chevron ×5, approach-chevron ×5, pump-chevron ×4) had no `aria-hidden`**, adding empty/meaningless nodes to the accessibility tree next to text that already describes the same action. Added `aria-hidden="true"` to all of them. Left the ~65 other inline SVGs alone (illustrative hero animations, all already wrapped in `<div class="page-hero-anim" aria-hidden="true">`, and a few content SVGs like `bloch-svg`/`lambda-svg` that may carry real diagrammatic content — not blanket-suppressed).
- **The single largest gap: ~250 `<label>` elements across 18 pages had no programmatic association with their input** (visually adjacent, e.g. `<div class="field-row"><label>Wavelength λ (nm)</label><input id="fib_lam">…</div>`, repeated across every calculator page — `lab-calculators.html` alone had 102 of these). Wrote a script that matches each "leaf" `<label>` (no nested `<label>`/`<input>`/`<div>`/`<select>` inside it — this excludes the site's existing correct wrapping-radio-label pattern) immediately followed by an `<input>`/`<select>` with an `id`, and adds `for="that-id"`. Applied across cavity-qed, cooling-simulator, dd-playground, fidelity-budget, imaging-calculator, lab-calculators, lab-techniques, laser-cooling, laser-locking, learn-quantum, mot-designer, release-recapture, remote-entanglement, rydberg-calculator, tof-calculator, zernike, plus one `<label class="sl-lbl">…</label><select>` instance each on absorption-imaging.html and tweezer-designer.html. Verified zero duplicate ids and zero orphaned `for` targets afterward.
- **13 range-slider inputs had no accessible name at all** (a visible caption in a sibling `<div>`/`<span>`, not a `<label>`, so screen readers announce nothing): 7 sliders on absorption-imaging.html (probe detuning, saturation, exposure time, pixel size, magnification, QE, read noise), 6 on tweezer-designer.html (trap wavelength, NA, power, Nx, Ny, spacing), 4 on polarimetry.html (ψ, χ, DOP, SNR), and the single pressure-explorer slider on vacuum-systems.html. Added `aria-label` to each, using the adjacent visible caption text.
- **The global search input (`js/main.js`) had no accessible name** beyond its placeholder (which screen readers don't reliably treat as a label). Added `aria-label="Search AMO Toolkit"`.
- Bumped `main.js?v=22→23` and `styles.css?v=19→20` (both files changed) across every page, `home.html`, and `404.html`; grep-verified exactly one version string of each remains site-wide.

## Corrections during verification (worth recording so the pattern isn't repeated)

- The research pass flagged `cooling-simulator.html`, `laser-cooling.html`, and `zernike.html` as having their `<footer>` nested *inside* the `.page-wrap` div, based on a stray `<!-- /page-wrap -->` HTML comment that appeared textually *after* the footer. Tracing actual div-nesting depth (not trusting the comment) showed the real closing `</div>` for `.page-wrap` was **earlier**, right after the last content `<section>` and *before* the "See Also" section and footer — matching the site's normal pattern. The comment was simply stale/misplaced from a past edit. First attempt at the `<main>` retag (trusting the comment) produced an unbalanced-div file; caught immediately by the tag-balance check, corrected using the verified depth-traced boundary. `dd-playground.html`'s footer genuinely *was* nested inside its wrapper (verified the same way) — that one's fix (closing `</main>` before the footer, moving nothing else) stands as originally applied.
- `mot-designer.html`'s `.page-wrap` div had no closing-comment marker at all (unlike its 13 siblings), which first looked like a real unclosed-tag bug; depth-tracing confirmed the div-count was balanced site-wide and located the actual close at line 730 — just missing its comment, not actually broken.

## Flagged, not changed — needs your call

- **9 pages skip `<h3>` and go straight from `<h2>` to `<h4>` for sub-panel titles** (cooling-simulator, decoherence-lab, fidelity-budget, imaging-calculator, laser-locking, learn-quantum, mot-designer, tof-calculator, laser-planner's one dynamic case), plus roughly 10 more pages with *partial* skips (some sections correctly nest h3, others jump straight to h4 — dd-playground, lab-calculators, laser-cooling, qc-landscape, vacuum-systems, lab-techniques, release-recapture, rydberg-calculator, rb-explorer, remote-entanglement). This is exactly the item the design audit deferred to "a future accessibility audit." Root cause confirmed: `h4` was chosen purely for its smaller default font-size (`css/styles.css` — `h3 { font-size: 1.2rem }` vs `h4 { font-size: 0.95rem }`), not for semantic level — there's no reusable "small heading" class. Fixing this properly means either (a) bumping every misused `<h4>` to `<h3>` and adding a class to preserve the current 0.95rem size, or (b) something else you'd prefer — and `laser-locking.html` is the worst case (only one `<h2>` in the entire file, an unrelated trailing "Sources" heading; its real tab-panel section titles have no heading level above them at all). This changes visual typography sitewide if done via a blanket font-size change, so I left it for your call rather than guessing at the right compromise.
- **`--text-muted` fails WCAG contrast in both themes.** Dark theme: `#475569` on `--bg-card`/`--bg-surface`/`--bg-base` computes to 2.41–2.65:1 (fails even the 3:1 large-text floor). Light theme: `#8c8066` computes to 3.16–3.58:1 (passes only for large text, fails 4.5:1 normal text). This token is used as `color:` 47+ times in the shared CSS plus in page-local `<style>` blocks on every one of the 28 pages (mostly small captions/units/hints, i.e. normal-text sizing where the large-text exception doesn't apply) — a real, sitewide, consequential failure, but picking a replacement hex that still reads as "quietly de-emphasized" rather than "as prominent as secondary text" is a design call, not a mechanical fix. Left the token as-is.
- **Zero screen-reader fallback for any of the 94 `<canvas>`/Chart.js graphics** across 26 pages (force curves, temperature plots, RB decay curves, coherence plots, etc.) — no `aria-label`, no adjacent data table, and no `.sr-only` utility class exists yet anywhere in the CSS to build one from. This is a real, uniform gap, but fixing it properly (even just a one-line `aria-label` summarizing what each chart shows, let alone a full non-visual data-table alternative) touches all 26 pages individually and is a bigger project than fits in one day's mechanical-fix budget. Flagging as a good candidate for a future focused pass — a `.sr-only` utility class would need to be added to `css/styles.css` first as the prerequisite building block.

## Confirmed clean (no action)

- **Images**: only 2 `<img>` tags exist site-wide (`laser-cooling.html`'s two cooling-animation GIFs) and both already have descriptive `alt` text. No missing-alt findings anywhere.
- **Accordion body visibility**: `.accordion-body { display: none }` / `.accordion.open .accordion-body { display: block }` is CSS-only and already accessible-safe — `display:none` removes content from the accessibility tree without needing a separate `aria-hidden`.
- **`aria-expanded` toggling for the standard `.accordion` component**: already correctly done at runtime by `initAccordions()` (`js/main.js`), not just present in static HTML — a genuine pre-existing positive, confirmed working before this pass touched anything.
- **Nav landmark, skip link, mobile overlay, and search dialog**: `renderNav()` already injects a real `<nav role="navigation" aria-label="Main navigation">`, a working skip-link (`.skip-link:focus{top:0}`), and correctly-labeled `role="dialog"` panels for the mobile menu and global search, with the hamburger's `aria-expanded` already toggled in JS. This part of the site was already a solid positive example — no changes needed.
- **Footer landmark**: every page's `<footer>` is a real semantic element, self-landmarking with no extra ARIA needed.
- **The 8 pages that already used `<main>` correctly** (absorption-imaging, amo-groups, cavity-qed, decoherence-lab, laser-planner, paper-syllabus, remote-entanglement, tweezer-designer) plus `404.html`: checked all of them for the same "footer nested inside main" mistake found and fixed elsewhere — all 9 already had `<footer>` correctly outside `<main>`. No action needed.
