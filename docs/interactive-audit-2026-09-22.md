## Fixed

**`pages/laser-cooling.html` — the Lamb-Dicke Parameter Calculator (`calcLD()`) was missing a factor of 2π converting the user-entered trap frequency to angular frequency, and a second, related factor of 2π in the recoil-energy ratio.** The calculator takes "Trap frequency ν (kHz)" as input — labeled and used everywhere else on this page (and site-wide) as the ordinary, experimentally-measured frequency — but its zero-point-motion formula plugged that number directly into `x0 = sqrt(ħ/(2·m·ν))`, which is only correct if the input were the *angular* frequency ω = 2πν. The adjacent KaTeX formula boxes had the identical bug: `H_trap = ħν(a†a+½)` and `x₀ = √(ħ/2mν)` both use ħν where the physics requires ħω. Two independent lines of evidence confirmed this is a real bug, not a notational quirk: (1) the page's own prose states "typical values: η ≈ 0.05–0.15 for optical tweezers with ν ≈ 50–200 kHz and λ ≈ 780 nm," but the buggy code produced η = 0.34–0.69 for that exact range — a factor of √(2π) ≈ 2.51 too high, self-inconsistent with the page's own stated range; (2) the *correct* version of the identical formula, `η = k·√(ħ/2mω)` with ω properly computed as `2π·ν`, already exists elsewhere on this site in `tweezer-designer.html` (line 279/709) and `cooling-simulator.html` (line 577) — this page was the one outlier. The companion "Recoil energy E_r / hν" readout had the same root bug: it computed `Er/(ħ·ν)` instead of `Er/(h·ν)` (i.e., missing the 2π converting ħ→h to match its own label), overstating the ratio by exactly 2π. Verified numerically in Python: for ⁸⁷Rb/780 nm the recoil frequency `E_r/h` is 3.77 kHz (matches the well-known literature value for the Rb-87 D2 line), giving a correct ratio of 0.0377 at a 100 kHz trap — the buggy code returned 0.2368, exactly 2π too large. Fixed by computing `omega = 2·Math.PI·nu` and using it in both the zero-point-motion and recoil-ratio formulas, and updated the three adjacent KaTeX boxes (`H_trap`, zero-point motion, Lamb-Dicke parameter) plus one prose sentence to display ħω/x₀(ω) with ω = 2πν spelled out, so the displayed math now matches what the calculator actually computes. The page's two *other* physics calculators on this same page — Sideband Cooling Limit (`calcSB`, a pure ratio `Γ/(4ν)` where the 2π cancels regardless of convention — verified against the page's own worked example, ⟨n⟩≈56 for Rb-87 in a 200 kHz trap) and Gray Molasses (`calcGM`, algebraically re-derived from its own displayed `s = (4η²γₕ+γ₋)/(η²γₕ+γ₊)` formula and confirmed identical) — were checked and are correct; only the Lamb-Dicke calculator had the bug. No shared `css/styles.css` or `js/main.js` edit was needed (the fix is page-local JS + KaTeX in `laser-cooling.html` only), so no cache-bust bump applies. Tag balance confirmed unchanged (301/301 divs, etc.) and the regression suite stayed green (11/11) after the edit.
