# Performance Audit Re-check — September 26, 2026

Scope: rotation re-check of the performance audit (page load performance for a static HTML/CSS/vanilla-JS site with no build step, no bundler, and no server — file weight, render-blocking resource order, CDN resource hints, image loading, CSS/JS duplication, dead code, cache-busting integrity). This was the most overdue item in the rotation: the original performance audit (`docs/performance-audit-2026-09.md`, 2026-09-11) had never been re-run, while every other original-menu audit had at least one re-check since (accessibility 09-20, cross-page-consistency 09-18, design 09-17, flow 09-19, interactive 09-22, link 09-16, navigation 09-23).

Method: re-verified each fix and flagged item from the 2026-09-11 report is still accurate given three months of site growth (29 → 34 HTML files, including three new comparison pages — `google-vs-ibm.html`, `psiquantum-vs-xanadu.html`, `quantinuum-vs-ionq.html` — and `start-here.html`), then did a fresh grep-based sweep for cache-busting drift, resource-hint coverage, and CDN tag consistency across all current pages. File count and check surface were small enough this round that a research subagent wasn't needed — everything was mechanical, verifiable with direct greps. Regression suite (11/11) kept green throughout; tag-balance (div/section/ul/li/html/body/head) was checked on every file touched and came back balanced on all of them.

## Fixed

- **`404.html` was serving a 5-versions-stale cached copy of `js/main.js`.** Every other one of the site's 33 HTML files references `js/main.js?v=31`, but `404.html` still pointed at `?v=26` — a cache-busting-discipline miss from some earlier batch of JS edits that bumped the version everywhere except the error page (its `styles.css?v=21` reference was correctly current, so this wasn't a blanket miss, just this one file/tag). A visitor landing on a broken link would have gotten a `main.js` build from five versions ago. Bumped to `?v=31` to match. Low risk: this only affects visitors who hit a 404, and the fix is a single query-string bump with no behavior change beyond "load current JS."
- **`amo-groups.html` and `paper-syllabus.html` were missing the site's entire Google Fonts loading block.** The original 2026-09-11 report noticed this and explicitly declined to touch it ("couldn't tell from the code alone whether it's a bug or a choice"). Resolved that ambiguity this round: both pages' own inline `<style>` blocks already reference `var(--font-mono)` (paper-syllabus also uses it in several places), meaning the intent was clearly to use the site's brand fonts (Source Serif 4 / JetBrains Mono) — but with no font link loaded, those variables were silently falling back to the CSS fallback stack (`'Fira Code', 'Courier New', monospace` / `'Iowan Old Style', Palatino, Georgia, serif`), so these two pages were rendering in different fonts than all 32 other pages. This is a genuine cross-page visual inconsistency, not a deliberate design choice — every other page uses the identical 3-line preconnect+stylesheet block. Added it verbatim (matching the pattern used site-wide) to both pages, right after the `<meta name="description">` tag. Neither page uses jsdelivr/Chart.js/KaTeX, so only the font preconnects were added, not the jsdelivr one (confirmed no page site-wide has an unused/wasted preconnect hint).

## Correction to a prior finding

- The 2026-09-11 report listed 6 functions in `js/main.js` as dead code with "zero call sites... in main.js's own init block or in any of the 29 pages' inline scripts": `initAssumptionBadges`, `initSourceConfidencePanels`, `initLabNotebook`, `initExpertModeToggles`, `initPagePlaybookPanel`, `initReferenceTrailPanel`. Re-checked all 6 this round: 5 are still genuinely dead (each has exactly one reference in the whole codebase — its own `function` declaration, no caller anywhere). But `initPagePlaybookPanel()` is now called from the `DOMContentLoaded` init block at the bottom of `main.js` (line 1833) and renders a live "Page Playbook" panel on tool pages with a matching `PAGE_PLAYBOOKS` entry. Either it was wired up sometime between 2026-09-11 and now as part of unrelated work, or the original finding missed the call site — either way, it should no longer be counted in the dead-code list. Not a code change, just correcting the record for whoever eventually acts on the CSS-duplication/dead-code cleanup flagged below.
