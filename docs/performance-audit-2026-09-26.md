# Performance Audit Re-check — September 26, 2026

Scope: rotation re-check of the performance audit (page load performance for a static HTML/CSS/vanilla-JS site with no build step, no bundler, and no server — file weight, render-blocking resource order, CDN resource hints, image loading, CSS/JS duplication, dead code, cache-busting integrity). This was the most overdue item in the rotation: the original performance audit (`docs/performance-audit-2026-09.md`, 2026-09-11) had never been re-run, while every other original-menu audit had at least one re-check since (accessibility 09-20, cross-page-consistency 09-18, design 09-17, flow 09-19, interactive 09-22, link 09-16, navigation 09-23).

Method: re-verified each fix and flagged item from the 2026-09-11 report is still accurate given three months of site growth (29 → 34 HTML files, including three new comparison pages — `google-vs-ibm.html`, `psiquantum-vs-xanadu.html`, `quantinuum-vs-ionq.html` — and `start-here.html`), then did a fresh grep-based sweep for cache-busting drift, resource-hint coverage, and CDN tag consistency across all current pages. File count and check surface were small enough this round that a research subagent wasn't needed — everything was mechanical, verifiable with direct greps. Regression suite (11/11) kept green throughout.

**Note on this run's own process:** two of the three items below looked, on first read, like fresh finds — but cross-checking against `git log`/`git show HEAD:<file>` before finalizing this report showed both were already fixed in local commits before this session started (one by Saumitra directly, one by a prior Claude session), and my own edits landed byte-for-byte identical to what was already committed. `git status` confirms zero working-tree diff for the three HTML files below. Recording that discovery here rather than claiming credit for fixes that predate this run.

## Already resolved (found via this round's re-check, but fixed before this session started)

- **`404.html`'s cache-busting `js/main.js?v=` reference.** The original 2026-09-11 report's convention (bump `?v=N` on every JS/CSS edit, across every HTML file) had drifted on this one file — it briefly showed `?v=26` while the rest of the site was on `?v=31`. A prior Claude session (commit `d752da7`) had already found and committed this exact fix. `git show HEAD:404.html` now matches the working tree exactly (`?v=31`) — no outstanding diff.
- **`amo-groups.html` and `paper-syllabus.html` missing the site's Google Fonts loading block.** The original 2026-09-11 report flagged this (both pages' inline styles reference `var(--font-mono)` but never loaded the font, so they were silently falling back to `'Fira Code'/'Courier New'` or `'Iowan Old Style'/Palatino/Georgia` instead of the site's actual `JetBrains Mono`/`Source Serif 4`) but declined to fix it, unsure whether it was a bug or a deliberate choice. Saumitra resolved that himself directly — commit `5460d65` (2026-09-25, the evening before this run) added the standard `preconnect`+stylesheet block to both pages, confirming it was indeed a bug. `git show HEAD:pages/amo-groups.html` and `...paper-syllabus.html` both match the working tree exactly — no outstanding diff.

## Correction to a prior finding

- The 2026-09-11 report listed 6 functions in `js/main.js` as dead code with "zero call sites... in main.js's own init block or in any of the 29 pages' inline scripts": `initAssumptionBadges`, `initSourceConfidencePanels`, `initLabNotebook`, `initExpertModeToggles`, `initPagePlaybookPanel`, `initReferenceTrailPanel`. Re-checked all 6 this round: 5 are still genuinely dead (each has exactly one reference in the whole codebase — its own `function` declaration, no caller anywhere). But `initPagePlaybookPanel()` is now called from the `DOMContentLoaded` init block at the bottom of `main.js` (line 1833) and renders a live "Page Playbook" panel on tool pages with a matching `PAGE_PLAYBOOKS` entry. Either it was wired up sometime between 2026-09-11 and now as part of unrelated work, or the original finding missed the call site — either way, it should no longer be counted in the dead-code list. Not a code change, just correcting the record for whoever eventually acts on the CSS-duplication/dead-code cleanup flagged below.
