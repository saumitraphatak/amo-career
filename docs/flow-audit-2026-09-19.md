## Fixed — cross-reference naming drift (found while verifying a research-pass finding, expanded into a full scan)

One research pass flagged a handful of "See Also" card labels using pages' pre-rename names. On inspection this turned out to be much larger than initially reported and to fit a clear pattern: this site has renamed several pages more than once over its history (confirmed via `git log -p` — e.g. `laser-cooling.html`'s `<title>` has been "Laser Cooling" → "Trapped Atom Cooling" → "Single-atom Cooling"; `rydberg-calculator.html`'s "Rydberg Calculator" → "Rydberg States & Blockade" → "Rydberg Blockade Calculator" → "Rydberg Blockade Lab"). Two of the three places a page's display name gets duplicated were already kept in sync by prior audits — `og:title`/`twitter:title`/JSON-LD `headline` by the 2026-09-16 technical audit, and the BreadcrumbList *category* name by the 2026-09-18 cross-page-consistency audit — but three other copies were not, and the drift compounds with every rename:

- **65 "See Also" card labels across 27 pages** pointed at a stale name for one of the pages they linked to (e.g. nearly every page linking to `lab-techniques.html` called it "Lab Techniques," never updated through two later renames to "AMO Lab Operations Handbook"; similarly "Rydberg Calculator" → "Rydberg Blockade Lab," "Gate Fidelity Budget" → "Rydberg Gate Error Budget," "Laser Cooling" → "Single-atom Cooling," and 15 more target names). Synced every stale label to its target's current `<title>`, cross-checked against `home.html`'s own tool-card name for the same page wherever one exists (all agreed, except the 3 pages noted below).
- **11 page-footer signature lines** ("‹Page Name› · AMO Toolkit · Saumitra Phatak · Purdue University") named the page itself using a stale pre-rename name — `laser-cooling.html`'s footer said "Laser Cooling Guide," a name that doesn't match its current title, breadcrumb, or hero at all. Synced all 11 to the page's current `<title>`.
- **10 BreadcrumbList JSON-LD leaf names** (the page's own name at position 3, distinct from the category name the 2026-09-18 audit already fixed at position 2) were similarly stale. Synced to current `<title>`.

Grepped afterward for any remaining instance of every corrected string site-wide (`pages/`, `home.html`, `index.html`, `llms.txt`, `llms-full.txt`) — none found outside the fixed locations. All fixes are text substitutions with no structural changes; `tests/formula_regression.py` was re-run after each batch and stayed 11/11 throughout, and div/ul/li/tr/td/section/table/span/a tag-balance was checked on all 28 touched files and came back clean. No shared CSS/JS files were touched, so no cache-bust bump was needed.
